jsonx tutorial

Learn jsonx in nine steps

jsonx is HTML templates plus plain JavaScript. You keep your data in ordinary variables, write ordinary functions that change them, and the templates that use those variables redraw by themselves. There's no build step and nothing to import.

Each step shows its code next to the result, and the result is live, so click and type in it. The code panels are read from this page and its files, so what you read is exactly what runs.

To use jsonx on your own page, load one file:

<script type="module" src="jsonx.js"></script>

1. Draw a value

A variable, and a template that draws it.


      

        
        

        

          
        

        
      

    


    
    
      
  • jx:data="user" draws the variable user with the <template> inside. The element is called a region.
    • 
      
  • {{name}} prints a value. It's always printed as text, never as HTML, so it's safe to print anything. {{a.b}} reaches inside.
    • 
      
  • When the name holds an object, its fields are the names you can use. Name several variables, jx:data="name city", and each is a name.
    • 
    

  


  
  

    
2. Events

    
Call a function on a click. The function only changes a variable, and jsonx redraws what uses it.


    

      

      

        
        

        

        

          
        

        
      

    


    
    
      
  • on:click="up" calls up() when the element is clicked. Any event works the same way: on:input, on:change, on:submit, on:keydown, or a component's own events.
    • 
      
  • After the function returns, jsonx compares the variables it can see with what they were, and redraws the regions that use the ones that changed. It only touches the parts of the page that are different.
    • 
      
  • The button doesn't have to be in the region. Nothing says what a button changes: jsonx works it out.
    • 
      
  • <if test="count"> draws what's inside only when count is truthy. More on that in step 4.
    • 
      
  • Not onclick: that's the browser's own attribute, and it runs its text as code.
    • 
    

  


  
  

    
3. What's typed

    
A function gets the values of the inputs around it, by their names.


    

      

      

        
        

        

          
        

        
      

    


    
    
      
  • A function gets one argument: the values. They're the named inputs in the element's region (or its <form>), like a form would send. Here that's { who: "…" }.
    • 
      
  • Redrawing never wipes what you're typing: jsonx updates the text around the input, not the input.
    • 
      
  • Modifiers go after a dot. on:input.delay-300="search" waits until typing stops for 300ms. on:keydown.enter="add" only listens for the Enter key (also escape, space, up, down…). And there's .once, .prevent and .stop.
    • 
    

  


  
  

    
4. Lists and choices

    
Repeat something for each item, show things only sometimes, and tell a function which item was clicked.


    

      

      

        
        

        

          
        

        
      

    


    
    
      
  • <each items="todos"> repeats what's inside for each item. Inside, names look in the item first, then outwards. Items with an id are tracked by it, so ticking one off only touches that row.
    • 
      
  • <if test="!todos">: a ! means false or empty. <else-if> and <else> come right after.
    • 
      
  • jx:vals="id" sends the item's id as a value, as it is (a number stays a number). Name several, jx:vals="id title", or rename one, jx:vals="todo=id".
    • 
      
  • When a value fills a whole attribute, like checked="{{done}}" or value="{{draft}}", it sets the live property, so the box and the input always match the data. That's how draft = "" empties the input. class:done="{{done}}" turns a class on and off.
    • 
      
  • on:submit stops the browser reloading the page, as you'd want.
    • 
      
  • Inside <table> and <select> the browser throws unknown tags out, so there you write the logic on the element: <tr jx:each="rows">, <option jx:if="x">, jx:else.
    • 
    

  


  
  

    
5. Your own components

    
Put a template in a .jx file, give it a tag name, and use it like any HTML element. Each one keeps its own state.


    

      

        

        
counter.jx

        

      

      

        
        

        

        

        
      

    


    
    
      
  • <template src="counter.jx"> loads the file. In it, a template whose id has a dash defines that element: <click-counter>.
    • 
      
  • The <script> inside the template is the component's code, with nothing to export. It runs once for each element, so the two counters count separately.
    • 
      
  • props="start:number" lists its attributes, and each is a variable in the script. Types are text (the default), number, boolean and json.
    • 
      
  • It draws into its own shadow DOM, so its <style> affects only the component, and <slot> works.
    • 
      
  • Its functions are methods too: document.querySelector("click-counter").reset() works from any other code.
    • 
      
  • Each one is a real web component (a Lit element). It works anywhere HTML does, inside React, Vue or plain pages, as long as jsonx is loaded.
    • 
    

  


  
  

    
6. Shared state

    
Components in different parts of the page can share data, with nothing passed between them.


    

      

        

        
shop.jx

        

      

      

        
        

        

        

          
          
          
        

        
        
      

    


    
    
      
  • A <script> at the top of a .jx file runs once, and is shared by every component in the file. Its variables stay in the file: another file can have its own count.
    • 
      
  • A prop the page doesn't set comes from the file's variable with that name. <basket-count> has props="count", so it shows the file's count, and redraws when it changes.
    • 
      
  • <buy-button product="tea"> sets its prop as an attribute, like any web component.
    • 
      
  • Click a button and only the count and the list redraw. The buttons don't use basket, so they're left alone.
    • 
    

  


  
  

    
7. Timers and lifecycle

    
Run code when a component appears and goes, and redraw after something that isn't an event, like a timer.


    

      

        

        
stopwatch.jx

        

      

      

        
        
        

        
        

          
        

        
      

    


    
    
      
  • Functions named connected, disconnected and rendered run at those moments. Hide the stopwatch and disconnected() stops its timer; show it and a new one starts.
    • 
      
  • In a component's script, el is the element, props holds its props, and refs.name is the element in its template marked jx:ref="name".
    • 
      
  • jsonx looks for changes after each event it handled. A timer, a fetch or a WebSocket aren't its events, so call jsonx.changed() after changing things. An async function called by an event is fine: jsonx checks again when it finishes.
    • 
    

  


  
  

    
8. Forms and form fields

    
A component can be a form field, so a form sends its value like an input's.


    

      

        

        
rating.jx

        

      

      

        
        
        

        

          

          
 

        

        

        
      

    


    
    
      
  • <template id="star-rating" form> makes a form field. Its value variable is what the form sends, under the element's name.
    • 
      
  • on:submit="send" on a form sends all its fields, the stars included.
    • 
      
  • Like an <input>, it fires change when you pick, so <star-rating on:change="…"> works too.
    • 
    

  


  
  

    
9. Events out of a component

    
A component can tell the page something happened, and leave the page to decide what it means.


    

      

        

        
picker.jx

        

      

      

        
        
        

        

        

          
        

        
      

    


    
    
      
  • jx:emit="pick" fires a pick event when clicked, carrying the item it was drawn for. The event bubbles out of the component.
    • 
      
  • on:pick="choose" on the page listens for it, like on:click. The event's item is added to the values, so choose gets { name, hex }.
    • 
      
  • colours:json takes JSON in the attribute. From a template, colours="{{list}}" passes the list itself.
    • 
      
  • To send something other than the item, use jx:detail='{"id": {{id}}}'.
    • 
    

  


  
  

    
Cheat sheet

    
Templates

    

      
{{name}}, {{a.b}}, {{.}}Print a value, always as text. {{.}} is the item itself

      
<each items="list">Repeat for each item. Names look in the item, then outwards

      
<if test="x">, test="!x"Draw if there, or if not there (false or empty)

      
<else-if test="y">, <else>The rest of the chain

      
jx:each, jx:if, jx:elseThe same, on an element, for tables and selects

      
value="{{draft}}"A whole-attribute value sets the live property

      
class:done="{{done}}"Turn a class on or off

      
jx:html="{{body}}"Draw HTML inside the element, cleaned of anything unsafe

      
<template jx:use="#id">Draw another template here

    

    
Data and events

    

      
jx:data="name"A region drawing the variable name, again whenever it changes

      
on:click="fn"Call fn(values) on that event. Any event works

      
on:load="fn"Call it straight away. With a <template> inside, the element draws what fn returns

      
.delay-300, .enter, .once, .prevent, .stopModifiers, e.g. on:input.delay-300, on:keydown.enter

      
jx:vals="id title"Send these values too. todo=id renames

      
jsonx.changed()Look for changes now, after a timer or other code

    

    
Components, in a .jx file

    

      
<template src="file.jx">Load a file of components

      
<template id="tag-name" props="a b:number">Define <tag-name>. Prop types: text, number, boolean, json

      
<script> inside the templateIts code, run once per element. Props are variables in it

      
<script> at the top of the fileShared by the file's components, and private to the file. Unset props come from it

      
connected, disconnected, renderedFunctions run at those moments

      
el, props, refs, jx:ref="name"The element, its props, and marked elements in its template

      
<template id="…" form>A form field: its value is sent under its name

      
jx:emit="pick", jx:detailFire an event carrying the item, for the page's on:pick
